# Launch demo: “Screenshot. Speak. Next Mac.”

## The idea

Show one real AI workflow across two Macs. The hook is the Xbox controller visibly doing useful work, not a lecture about its bindings. Aim for a 55–70 second finished edit. Record each section slowly with two seconds of stillness before and after; we can tighten the edit without faking response time.

Keep the pink controller low in frame, both thumbs visible, and the important screen content above it. Use one clean-screen pop-out for the screenshot/dictation sequence and one for the second Mac. Preserve at least one continuous wide POV shot of the cross-Mac move.

## Before rolling

- Use a demo project with no secrets or customer information. On the left Mac, show a simple local website with an obvious visual improvement to make. On the right, open a separate prepared Codex task and preview. Enlarge the relevant UI so viewers can read it in a phone-sized feed.
- Test the exact screenshot → clipboard → paste → dictation → submit flow on both machines. Screenshot capture alone does not attach an image: with Gabe's clipboard screenshot shortcut, return focus to the composer and press **Y** to paste.
- Verify app-specific mappings on the lead Mac and the global fallback on the other. The receiving Mac must already have its matching dictation shortcut configured. Do not imply Vibe Controller provides speech recognition itself.
- Record the phone in a fixed orientation. Brace the neck mount to reduce swing, lock focus/exposure for the displays, and do a 10-second test for readability and screen banding. Clean the screens, remove the spray bottle/loose items, tuck cables behind the laptops, and leave the real setup recognizable.
- Start the phone first. Start a local screen recording on the second Mac. Start Demo Capture on the lead Mac, filming its START slate. On the second Mac, briefly reveal then dismiss a large unique take label visible in both its screen recording and the phone. Repeat the cue there at the end. These are independent clocks; we align by visible frames, not by hoping simultaneous clicks were exact.
- Turn on Do Not Disturb on both Macs. Keep the first take short. Film the END slate before stopping, then preserve all original files.
- For the optional upward jump, select both lead-Mac displays in Demo Capture and leave Follow cursor enabled. The automatic review movie will switch screens, while both originals remain available for the floating-screen effect. Check disk space before the session and review/remove false starts in Finder once a good take is confirmed; the app does not delete footage for you.

The timing is an editing target, not a demand to rush your hands or the actual software. If dictation takes longer, shorten the request or let the finished edit run a little longer.

## Optional inserts, not more material crammed into the main cut

**Appshot (5–7 seconds):** on the lead Mac, hold LB and press RB to send the configured left-Command + right-Command chord, with Codex's Appshot flow ready. Show the real attachment/selection behavior for the installed Codex version. This is an alternative to the screenshot hero shot or a follow-up clip, not a second explanation of the same idea.

**OCR (6–8 seconds):** X → TextSniper region selection with LT + stick → focus destination → Y. Caption it “OCR via TextSniper (separate companion app).” This demonstrates optional OCR accurately without implying it is bundled.

**Vertical handoff (3 seconds):** LB + D-pad Up to the external monitor, move/click there, then Down. Use this only if the main two-Mac handoff is already clear.

**Correction (2 seconds):** a deliberate small edit using R3 for Backspace. Don't manufacture an error just to show every button.

I'd omit the Codex micro comparison from the opening. “I already had this controller” makes the point without relying on viewers knowing another product, and keeps the focus on your idea. If you want the comparison, put it in the post or a reply.

## Compositing and honesty

Back to front: original POV → tracked clean screen replacement → animated screen pop-out → original hands/controller/forearms/cable matte → small captions. Expand mostly upward. A foreground matte cannot recover a hand that leaves the camera frame.

First make a 15–20 second proof of the screenshot/dictation moment, inspecting fast thumb movements and cable edges. Approve that treatment before applying it to the whole film. Button logs suggest highlight cues; the actual recorded UI determines when a result appears.

This should feel like convincing evidence of an unusual workflow—not a feature checklist or a promise that nobody will ever need a keyboard again.

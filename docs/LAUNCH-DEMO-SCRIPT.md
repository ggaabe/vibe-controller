# Launch demo: “Building Vibe Controller with Vibe Controller”

## The idea

Show yourself using Vibe Controller to work on Vibe Controller itself. Keep the running app on the upper external monitor and Codex, open to this actual repository, on the main laptop screen directly below. Viewers can connect your physical button presses to the animated controller above and the resulting work below. No dummy website or throwaway demo project.

Aim for a 60–80 second finished edit. Record each section slowly with two seconds of stillness before and after; we can tighten the edit without faking response time. The second Mac is a brief demonstration of continued control across computers, not a second feature tour.

## Screen layout and framing

- **Upper monitor, attached to the lead Mac:** Vibe Controller stays here throughout the take. Select the Controller view, keep Show labels on, and enlarge the window until stick movement, trigger fills, and button highlights are easy to see. Keep the live map unobstructed except while capturing it. Close diagnostics or unrelated settings unless they are the subject of the request.
- **Main laptop immediately below, also the lead Mac:** Codex is open to the actual `vibe-controller` project, with the relevant task and composer visible. Keep unrelated task history and private information out of view.
- **Second laptop to the right:** prepare one genuine follow-up concerning this app, such as reviewing its README setup instructions. Use an existing safe Codex task with that context ready. Do not run competing edits to the same files on two computers.
- **Physical pink controller:** keep it low in the phone frame, both thumbs visible. Frame the upper live map and lower Codex window together for the core demonstration. If including the second laptop makes both unreadable, use a separate wider take for the cross-Mac sequence.

The visual chain is **hands → live controller map above → screenshot and dictated request in Codex below**. The app stays on the lead Mac even while you control the second laptop. Label the upper screen as an external display, not another computer.

## Before rolling

- Use this real repository and choose one small UI improvement you genuinely want. A good candidate is the readability of the controller's action labels: they give the screenshot a clear target while the live map remains useful. Adapt the dictated request to what actually needs changing in the installed build; don't introduce an artificial defect.
- Preserve the current working changes, especially the USB/haptics work. Do not reset the repository between takes. Ask for a contained UI-only change, and review the diff before any build/install. Do not quit or replace the running controller app during the input demonstration; show a rebuilt result in a separately recorded, clearly labeled later shot if desired.
- Inspect the real Codex task, its sidebar, terminal output, and both recorded displays for private material before rolling. Use a clean task within this same project if needed; the project itself is not a dummy.
- Test the exact screenshot → clipboard → paste → dictation → submit flow on both machines. Screenshot capture alone does not attach an image: with Gabe's clipboard screenshot shortcut, return focus to the composer and press **Y** to paste.
- Verify app-specific mappings on the lead Mac and the global fallback on the other. The receiving Mac must already have its matching dictation shortcut configured. Do not imply Vibe Controller provides speech recognition itself.
- Record the phone in a fixed orientation. Brace the neck mount to reduce swing, lock focus/exposure for the displays, and do a 10-second test for readability and screen banding. Clean the screens, remove the spray bottle/loose items, tuck cables behind the laptops, and leave the real setup recognizable.
- Start the phone first. Start a local screen recording on the second Mac. Start Demo Capture on the lead Mac, filming its START slate. On the second Mac, briefly reveal then dismiss a large unique take label visible in both its screen recording and the phone. Repeat the cue there at the end. These are independent clocks; we align by visible frames, not by hoping simultaneous clicks were exact.
- Turn on Do Not Disturb on both Macs. Keep the first take short. Film the END slate before stopping, then preserve all original files.
- Select **both the upper monitor and main laptop display** in Demo Capture. Both are essential now: one records the live map and the other records Codex. Follow cursor may be useful for the review movie, but it is not the final edit: preserve the two synchronized originals so the map can remain visible while the cursor is on the laptop or other Mac. Check disk space before the session and review/remove false starts in Finder once a good take is confirmed; the app does not delete footage for you.
- Rehearse with the currently reliable controller transport. This sequence does not require Share or vibration, so do not depend on the unresolved Full USB vibration/session issue for the take. Verify native handoff separately rather than treating Full USB input as its on/off switch.

## Optional inserts, not more material crammed into the main cut

**OCR (6–8 seconds):** X → TextSniper region selection with LT + stick → focus destination → Y. Caption it “OCR via TextSniper (separate companion app).” This demonstrates optional OCR accurately without implying it is bundled.

**Finished improvement (4–6 seconds, recorded later):** after reviewing and building the real UI change, show the result in Vibe Controller on the same upper monitor. Label the cut **After the change** or **Later**. Move the stick again so viewers see that the animation still works. Do not rebuild over the app mid-demonstration or imply the edit completed in the time of the cross-Mac cutaway.

**Correction (2 seconds):** a deliberate small edit using R3 for Backspace. Don't manufacture an error just to show every button.

I'd omit the Codex micro comparison from the opening. “I already had this controller” makes the point without relying on viewers knowing another product, and keeps the focus on your idea. If you want the comparison, put it in the post or a reply.

## Compositing and honesty

Back to front: original POV → tracked clean screen replacement → animated screen pop-out → original hands/controller/forearms/cable matte → small captions. Preserve the top-monitor/laptop relationship. When Codex lifts forward, leave room for the upper live map, or use a synchronized crop of its controller as a small companion panel. A foreground matte cannot recover a hand that leaves the camera frame.

Keep both recordings from the same take aligned: the controller map is visual feedback, not an exact timing instrument. Its displayed input is UI telemetry, so don't shift its highlights earlier to make response appear faster. Do not substitute rendered button presses or a replay for the live app footage.

First make a 15–20 second proof of the screenshot/dictation moment, inspecting fast thumb movements and cable edges. Approve that treatment before applying it to the whole film. Button logs suggest highlight cues; the actual recorded UI determines when a result appears.

This should feel like convincing evidence of an unusual workflow—not a feature checklist or a promise that nobody will ever need a keyboard again.
